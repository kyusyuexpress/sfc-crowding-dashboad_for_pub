1問題設定

「日付 d の30分枠 t に、キャンパスに何人いるか」を、その日の時間割から予測する回帰問題として扱います。

授業API時間割・教室・学事暦
1か月先まで取得できる
特徴量30分枠ごとの授業人数 C(d,t)、第何週か w など
モデル下の M1〜M6 から選ぶ
予報 ŷ(d,t)30分刻み・1か月先まで
Wi-Fi 実測 y(d,t)端末数 ÷ 1.5
→ 誤差 |y − ŷ|
↺ 実測がたまるたびに、係数を学習し直す

授業人数 C(d,t) の作り方

教室の定員 × 推定履修率 r定数・仮置き = 推定履修者数授業ごと
Σ 推定履修者数30分枠 t に開講中の授業すべて = C(d, t)

教室の定員データ（sfc_classrooms.json / kyousitu_size.json）は、いまリポジトリにサンプルしかありません。 下の図では、代わりに「開講中の授業数」を使っています。

2授業人数に係数をかけるだけでは足りない理由

10/5（月）の実際の時間割で、30分枠ごとの開講授業数を数えました。 「授業人数 × 係数」だけで予報すると、形はこの棒グラフのままになります。

ずれる場所授業人数だけの予報実際（想定）足りないもの
昼休み（12:40–13:00）0人むしろ多い（食堂など）授業の合間に残る人
時限の境目階段状に急変するなだらかに変わる授業の前後に早めに来る人・残る人
朝・夜0人研究室・自習・サークル授業以外の人（ベース）
学期の後半第1週と同じ減っていく第何週かによる出席の変化

つまり「授業人数 × 係数」の式には限界があります。 授業人数を土台にしつつ、時間方向のならしと授業以外の人（ベース）を足す必要があります。 下の M2〜M5 は、それを段階的に足していった案です。

3学習できる変数・できない変数

目標は「すべての変数を機械学習で決める」ことですが、かけ算でつながった変数どうしは、データから区別できません。

Wi-Fi 端末数 = 1.5端末／人 × 定員 × r履修率 × 出席率第何週かで変わる ＋ ベース
データから学習する固定値（定数か外部データ）

1.5 × r × 出席率 は、データからは1つの積としてしか推定できません。 たとえば、r を 0.8 から 0.4 に変えても、学習で出席率が2倍になり、予報はまったく同じになります。 そこで、

  • 1.5 と r は固定し、モデルは「推定履修者のうち何割が来ているか」を表す係数 a を1つだけ学習する。
  • r の値が効くのは、学期中のデータがまだない最初の数日の予報と、係数 a を解釈するときだけ。
  • 1.5 や r を個別に確かめたいなら、別の正解データ（実際の履修者数、人手で数えた人数など）が必要。

4モデル案

どの案も、30分枠ごとの実測 y(d,t) に対する回帰として学習できます。 M1〜M5 は係数に対して線形なので、制約（係数は0以上など）付きの線形回帰で学習でき、1週間分程度のデータでも回ります。

記号：C(t) は30分枠 t の授業人数、b(t) は時間帯ごとのベース、w は学期の第何週か、g(w) は週による出席の変化

M0

前週の同じ曜日・同じ時刻

ŷ(d,t) = y(d − 7日, t)
  • 学習が要らない。比較の基準（ベースライン）になる
  • 1週間より先を予報できない。第1週は使えない
参照用。他の案がこれに勝てるかを見る
M1

授業人数 × 係数

ŷ = a · C(t)
  • いちばん単純。パラメータは1個
  • 上の図のとおり、昼・朝・夜が0になり、階段状になる
パラメータ 1
M2

時間帯ごとのベースを足す

ŷ = b(t) + a · C(t)
  • 朝・夜・昼休みの底上げを、時間帯ごとに学習できる
  • 時限の境目の段差は残る
パラメータ 約27（30分枠の数 ＋ 1）
M3

授業人数を前後にならす

ŷ = b(t) + Σₖ wₖ · C(t − k)
  • 授業の前後に早めに来る人・残る人を、重み wₖ としてデータから学習する。人が決めるのは見る範囲（k の範囲）だけで、ならし方の形は決めない
  • 段差と昼休みの谷が自然に埋まる
  • 重みが負にならないよう、制約が必要
パラメータ 約31。M7 に統合
M4

今日の授業をすでに終えた人・これから受ける人

ŷ = b(t) + a₁C(t) + a₂C済(t) + a₃C後(t)
  • C済：今日すでに終わった授業の人数、C後：今日これから始まる授業の人数。「今日キャンパスにいる理由がある人」を表せる
  • 同じ学生が複数の授業を取るので、二重に数える。その分は係数に吸収させる
パラメータ 約30
M5

1日の総量 × 1日の中での形

ŷ = D(d) · p(t | d)
  • D(d)：その日の総人数（当日の授業人数の合計から予測）、p：時間帯ごとの割合（授業パターンをならしたもの）。1日の水準と形を分けて学習できる
  • 二段構えで、実装がやや複雑
パラメータ 少なめ
M6

勾配ブースティング（LightGBM など）

ŷ = f(C(t±k), C済, C後, t, 曜日, w, …)
  • 非線形な関係も、変数どうしの組み合わせの効果も拾える
  • 数週間分のデータが要る。1か月先への外挿（第何週かの効果）が苦手
データが十分たまってから比較する。詳しくは おまかせ予報の戦略

M7 統合案（採用）：出席率を係数に分解し、ならし方も学習する

M2・M3 に、出席率を掛け算に分解した係数を組み合わせます。

ŷ(d,t) = b(t) ← 授業以外の人 + exp(β曜日 + γ週) × Σₖ wₖ · C(d, t − k) ← 授業由来の人 k = −4〜+4（前後2時間）

固定する（人が決める）

  • 端末／人 1.5、推定履修率 r
  • 基準：月曜 = 1、第1週 = 1（係数は比率として学習）
  • 見る範囲：前後 ±2 時間
  • 重みのなめらかさの罰則の強さ（検証データで選ぶ）

学習する（データが決める）

  • b(t)：時間帯ごとのベース（約30）
  • wₖ：ならし方の重み（9）
  • β曜日：曜日係数（4）
  • γ週：週の係数（指数的な減衰なら1）

ならし方もモデルが決める

前後の授業人数 C(t−4)…C(t+4) を別々の特徴量として渡し、重み wₖ を学習します。 「授業の何分前から来るか」「終わってからどれだけ残るか」は、学習した重みとして出てきます。 ならし方を人が固定すると情報が失われて学習しにくくなるので、人が決めるのは見る範囲だけにします。

  • パラメータは約45個。掛け算を含むので普通の線形回帰にはなりませんが、scipy の最小二乗や PyTorch で学習できます。
  • 時計の時刻ごとの係数 δ(t) は wₖ と役割がかぶるので、最初は入れません。
  • データがたまったら、同じ特徴量を M6（勾配ブースティング）に渡して比べます。

第何週かによる出席の変化 g(w)

M1〜M5 の授業の項（a や wₖ）に、共通のかけ算として足します。M7 の exp(γ週) がこれにあたります。どれも学習で決める前提です。

形式パラメータ特徴
なしg(w) = 10第1週のデータしかないうちはこれ
指数的に減るg(w) = exp(−λ(w − 1))1少ないデータでも推定でき、1か月先へも自然に延ばせる
下限ありで減るg(w) = g∞ + (1 − g∞)·exp(−λ(w − 1))2「ある水準で下げ止まる」を表せる。数週分のデータが要る
週ごとに自由g(1), g(2), …週の数形を仮定しないが、まだ来ていない週は予報できない
